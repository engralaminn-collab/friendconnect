# FriendConnect — Real Phone Call Test Procedure

This is the ONLY manual test required. Everything else is automated.

## Prerequisites

1. FriendConnect deployed on production server with:
   - HTTPS (Caddy)
   - MySQL
   - Redis
   - Coturn TURN server (installed via `sudo ./coturn/install.sh`)
   - VAPID keys (auto-generated by `./scripts/production-install.sh`)
2. Verify before testing: `curl https://YOUR_DOMAIN/api/webrtc/health`
   - Must show `turn: ok`
3. Two real devices on **different networks**

---

## Test: Phone A (Android + Mobile Data) calls Phone B (iPhone + WiFi)

### Phone A (Android, Mobile Data)
1. Open Chrome
2. Go to `https://YOUR_DOMAIN`
3. Login with your account
4. Open the Chats tab
5. Tap a friend's conversation
6. Tap the **video call** icon

### Phone B (iPhone, Home WiFi)
1. Open Safari
2. Go to `https://YOUR_DOMAIN`
3. Login with a different account
4. Wait for the incoming call notification
5. Tap **Accept**

### Verify on BOTH phones:
- [ ] Call connects (status shows "Connected")
- [ ] You can HEAR each other (audio works both ways)
- [ ] You can SEE each other (video works both ways)
- [ ] Tap **Mute** → other person can't hear you → tap again → they can
- [ ] Tap **Camera Off** → video freezes → tap again → resumes
- [ ] Tap **Switch Camera** → camera flips (front ↔ back)
- [ ] Call timer is counting up
- [ ] Tap **End Call** → call ends cleanly on both phones
- [ ] Check Calls tab → call appears in history with correct duration

### Reverse: Phone B calls Phone A
1. Phone B: open Chats → tap friend → tap video call
2. Phone A: accept the call
3. Verify all the same checks above

---

## Network Transition Test

1. Start a call with Phone A on WiFi
2. On Phone A: turn off WiFi (switch to Mobile Data)
3. Verify:
   - [ ] Call shows "Reconnecting..." briefly
   - [ ] Call reconnects within 5-10 seconds
   - [ ] Audio/video resumes
   - [ ] If reconnection fails → call ends gracefully (not frozen)

---

## Test Matrix

| From | To | Result |
|------|----|--------|
| WiFi | WiFi (same network) | Should work (P2P) |
| WiFi | WiFi (different ISP) | Requires TURN |
| WiFi | Mobile Data | Requires TURN |
| Mobile Data | WiFi | Requires TURN |
| Mobile Data | Mobile Data | Requires TURN |
| Bangladesh | Different country | Requires TURN |

**All cross-network tests require a working TURN server.**

---

## If Calls Fail

1. Check `https://YOUR_DOMAIN/api/webrtc/health` — is TURN `ok`?
2. Check `https://YOUR_DOMAIN/api/webrtc/diagnostics` (logged in) — recent calls show `failureReason`?
3. Check Coturn: `./coturn/healthcheck.sh`
4. Check firewall: ports 3478 (TCP/UDP), 5349 (TCP), 49152-65535 (UDP) must be open
5. Check browser console for ICE errors
6. Verify HTTPS (camera/mic requires secure context)

## Acceptance Criteria

**A call is successful only when:**
- Real audio flows between two devices on different networks
- Real video flows between two devices on different networks
- All controls work (mute, camera, switch, end)
- Call history records the call

**Do NOT mark calls as production-ready until this test passes on real devices.**
